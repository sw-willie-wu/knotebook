# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Knotebook follows Keep a Changelog conventions: unreleased work accumulates under [Unreleased] and moves into a dated version section once it ships. The first release is v0.1.0.

## [Unreleased]

### Added

- Notes can contain Mermaid diagrams. Insert one with `/diagram` (`/圖表` in Traditional Chinese) from the slash menu, click a diagram to edit its source, then press Escape or click away to draw it again. Pasting a ```mermaid fenced code block turns it into a diagram automatically — including diagrams produced by the AI actions — and the button in a diagram's top-right corner opens the source as well — labelled Edit, or Show source for readers, who get the same text read-only. Diagrams follow the light/dark theme. When the source has a syntax error the block shows the message next to the source, so it stays editable rather than becoming an opaque failure. Copying a diagram out of Knotebook produces the ```mermaid source rather than an SVG, so it renders on GitHub or Obsidian and can still be edited there. Diagrams cannot pull in remote resources: Mermaid lets a diagram name external images and CSS and its own sanitizer keeps them, so Knotebook strips remote references out of the rendered SVG — opening a note never contacts a host the diagram author picked. Mermaid itself is loaded only the first time a note actually draws a diagram, so notes without diagrams download nothing extra (#94).

### Changed

- A selected block now gets a 2px outline in the theme's accent color instead of BlockNote's built-in 4px bright blue. The blue was hard-coded, so it ignored both the light/dark theme and the chosen accent color, and on a large block — an image, a file, a diagram — it read as a thick blue frame around the whole thing rather than a selection cue.
- The backlinks row's horizontal scrollbar is now thinner than the app's other scrollbars (6px instead of 10px) and sits at the very bottom of the row, with a clear gap between it and the chips above. It used to be full-width thickness crowded against the chips in a 36px-tall row, and further from the card's bottom edge than it needed to be.
- In the backlinks row, the horizontal scrollbar now always reserves its space, and the label is aligned to the same optical centre line as the chips. Previously the scrollbar only appeared once there were more chips than fit, and it took its 10px out of the chips' half of the row — so the chips sat about 5px higher than the label exactly when a note had many backlinks (#90).
- The backlinks strip at the bottom of a note is now a single row — the "Mentioned in N notes" label sits inline with the source chips, which scroll sideways when there are more than fit — and it is always present, showing "No mentions yet" when nothing links here. Previously the label sat on its own line above a wrapping list of chips, and the whole strip disappeared when a note had no backlinks, which made the feature invisible on any note nobody had linked to yet and let the note card's height jump around. The row is the same height as the account row at the bottom of the sidebar, so the two line up.

- The note's text column now scales with the window instead of stopping at a fixed 680px: it takes 85% of the scrolling area's width, between 680px and 1056px. Windows up to about 1100px wide keep the column they had — 680px is the floor, and a window narrower than that still gets a full-width column — while on wider screens the article grows with the card instead of sitting as a narrow strip between two large empty margins (#87).

## [0.3.1] - 2026-08-26

### Changed

- Scrollbars throughout the app — the note content, the sidebar's note list, the AI panel, the settings dialog and any other scrolling area — are now a thin, rounded, semi-transparent grey that follows the light/dark theme, instead of the operating system's default scrollbar. The track is transparent and the thumb gains contrast on hover (darker in light mode, brighter in dark mode). In Firefox the browser's native thin scrollbar is used, in the same theme-following grey but without the hover effect. On macOS this also means scrollbars are always visible in their own 10px gutter rather than overlaying content and auto-hiding: styling a scrollbar opts that scroll area out of the system's overlay scrollbars (#84).
- The six accent-color dots in the user menu now show which one is selected with a checkmark inside the dot instead of a ring around it — the ring's contrast against the light theme's popover fell short of WCAG's 3:1 minimum, and it shared the same ring slot as the keyboard focus ring, which overrode it, so a focused dot lost its selection cue. The keyboard focus ring itself is unchanged and no longer competes with anything: focus and selection are independent now, so a focused, selected dot shows both at once. The accent-color group of dots also gained an accessible group name (`aria-labelledby`) tied to its "Accent color" heading (#78, #79).
- Traditional Chinese accent color names changed: 青 → 青瓷, 鼠尾草綠 → 鼠尾草, 粉 → 玫瑰. The English names, and the indigo/blue/gold names in both languages, are unchanged (#80).

## [0.3.0] - 2026-08-26

### Changed

- Dark mode's palette is now a neutral dark grey with a slight cool tint, replacing the near-black default, and layered in three visible steps — page background darkest, cards a step lighter, floating surfaces (dialogs, toasts, the BlockNote slash menu/formatting toolbar/tooltips) lighter still — instead of cards and floating surfaces sharing one shade. BlockNote's editor surface and its floating menus now match this scale instead of showing their own built-in dark colors (#75).
- The main layout is now built from cards floating on a deeper background instead of flat, edge-to-edge panels: the sidebar, the note's content, and the AI panel each sit in their own bordered card, while inputs and outline buttons keep the page's background color rather than the card's, so they read as inset into whatever surface they sit on. The sidebar note list now groups into Recent / My notes / Shared with me, with a title search box above it (Ctrl/Cmd+K focuses it, Escape clears it and moves focus away). Deleting a note has moved off the sidebar row and into the note's own ⋮ menu in its header, alongside a new "Copy link" entry; the sidebar itself no longer has a delete button. Backlinks are now a row of chips at the bottom of the note instead of a collapsed section that had to be expanded to see anything. The light theme's page background is now a light grey instead of pure white, to give the new cards something to float on top of — a visible change for anyone using it (#76).
- Knotebook now offers six accent colors — Indigo (the default), Blue, Teal, Sage, Rose and Gold — picked from a row of color dots in the user menu, below the theme setting. The chosen accent tints four places: the "K" wordmark, the sidebar's selected note row, the "New note" button, and a note's share icon. This changes the default look for everyone, not just people who open the picker: those four places used to be neutral and are now tinted Indigo out of the box, and the "New note" button in particular went from a solid filled button to a soft translucent tint of the accent color. As with the theme setting, the choice lives only in this browser's local storage; it is not synced across devices or saved on the server (#77).

## [0.2.0] - 2026-08-25

### Security

- An embedded image, video, audio or file URL is now checked again when it is rendered, not only when it is typed into the embed field. Note content is a collaborative Yjs document, so any collaborator with edit access can write block properties directly and bypass the input check entirely — a `javascript:` or `data:` URL written that way went into every other reader's document unfiltered (inert in an image or media `src`, but it had no business being there). Uploaded files keep working: the render-side check deliberately accepts the relative URLs uploads produce. A URL that fails the check renders as a broken image or player rather than being fetched (#12).
- An AI provider's stored API key is now cryptographically bound to the provider it belongs to, so a key that ends up under the wrong provider is reported as undecryptable instead of being used. The ciphertext was AES-256-GCM but carried no associated data, so a key copied into another provider's row decrypted just fine and that provider would happily send it upstream — which is how a row restored from an old backup, or a hand-written `UPDATE`, could silently start billing someone else's account. This is an integrity check rather than a defence against an attacker who can already write to the database: anyone who can move ciphertext between rows can also point a provider's base URL at a host they control and read the key in plaintext. Old ciphertexts still decrypt and are rewritten in the new format on the next start (including disabled providers; a failed rewrite is logged and retried next time, never blocking startup). **The rewrite is one-way** — see [Known limitations](docs/known-limitations.md) before rolling back to an older version (#14).
- Changing an AI provider's Base URL now clears its stored API key. The key is sent in plaintext to whatever host that field names — by design, that is what a provider is — so until now any administrator could point an existing provider at a host they controlled, press Test, and receive a key they were never able to read back through the UI. Supplying a new key in the same edit keeps the provider working in one step, the Settings UI warns before saving, and a provider with no key stored now says so on its card. Editing a provider without touching its URL does not clear anything. This does not make an untrusted administrator safe — they can still point a provider somewhere and wait for a key to be entered again, which is now visible rather than silent, and logged with the account and the old and new host. See [Known limitations](docs/known-limitations.md) (#46).
- Copying a note block to the clipboard, and the markdown handed to an AI quick action, now pass embedded media URLs through the same check that rendering does. The #12 fix guarded every place a URL enters this app's own pages, but export took the raw stored URL — so copying a block a collaborator had poisoned pasted `<a href="javascript:…">` or `<img src="javascript:…">` into whatever application received it, and an AI action sent the raw URL upstream. Not an XSS in Knotebook itself (that path was already closed), but poisoned content should not leave the app either. A URL that fails the check is exported as `about:blank`; uploaded files and ordinary web links export unchanged (#43).
- The server now notices when a note's document contains a media URL with a scheme like `javascript:` or `data:`, and says so in the log. Note content is writable by any collaborator with edit access, and the client-side guards (#12, #43) replace such URLs everywhere they could do harm — but the string itself stays in the document indefinitely, invisible to whoever runs the instance. On save, the server scans media-URL fields and logs one warning per note per load cycle naming the note, the schemes and the block types (never the URL itself, and never more than one line however often the note saves). It deliberately does not rewrite or reject anything: teaching the server to validate document content is a design decision this change does not make. See [Troubleshooting](docs/self-hosting.md#troubleshooting) (#44).
- A collaboration connection that keeps sending messages the server cannot handle is now dropped. The collaboration library's reaction to such messages — an unknown message type, a type its enum names but its handler has no case for (`SyncStatus`/`Ping`/`Pong`), or an authentication message of a kind only servers send — is to write an unstructured error line and carry on, without closing the connection or counting against any of this app's log throttles; a signed-in user connected to their own note could therefore write to the server's log at close to line speed for as long as they liked. Those messages are now classified against the set the library actually handles and dropped before they reach it; a connection that accumulates ten of them is forcibly disconnected, leaving one log line naming the note, address and message type — that line itself capped process-wide at ten per minute, since it can be triggered before anyone is signed in. The tolerance exists because an unknown type can also be a newer client talking to an older server during an upgrade; the flip side, recorded in [Known limitations](docs/known-limitations.md), is that a future client version introducing a frequent new message type would see its connections dropped until the server is upgraded too. As a second layer, the compose file now caps the `app` container's log size (50 MB × 5 files) so any future log-writing path degrades into rotation rather than a full disk (#50).

### Fixed

- Test-only: the note page's error screen now has an integration test pinning that opening and closing the settings dialog on top of it does not trigger a page reload. The error boundary added in #66 deliberately keys its "user navigated away, reload to recover" behaviour on the note reference from the URL rather than the router's location key, because closing the settings dialog navigates back to a saved location and that produces a fresh location key — keying on it would turn "close the dialog" into a surprise full-page reload. That choice was only recorded in code comments; switching it back would have kept every existing test green. The new test walks the real route tree through open-settings/close-settings on a failed note page and asserts zero reloads, alongside positive controls proving the reload spy actually intercepts the boundary's default reload path on both lifecycle routes. The same change also hardens two pre-existing settings-dialog tests that waited on the note page's real lazy import with the default one-second timeout — the only such waits in the suite, and intermittently red under a cold, loaded worker even without this branch (#68).
- A note page whose code chunk fails to load — the tab is offline, or a deploy rotated the asset hashes out from under an open tab — no longer strands the user on a blank white page. The note editor's code is loaded on demand (#19), and a failed load used to escape as an uncaught render error that unmounted the entire app. Now, when the failure looks like a deploy rotation (the network is up and this tab's one automatic retry hasn't already been spent), the page reloads itself once — picking up the new asset hashes, usually without the user noticing; the retry budget is re-armed each time a chunk load succeeds, and a genuinely broken deploy degrades to an error screen instead of a reload loop. In every other case — offline, retry exhausted, storage unavailable, or a crash inside the note page itself rather than a chunk failure — the app shell stays up with a message and a retry button, and navigating to another note from the sidebar — when the network is up — recovers via a reload too. As a backstop, the whole app is now wrapped in a top-level error boundary, so *any* unhandled render error shows a "Something went wrong — Reload" screen instead of a white page. The chunk-failure detection matches known browser, bundler and reverse-proxy error messages (a failed load of this chunk usually surfaces as Vite's CSS-preload error, not a bare failed import) and the one-reload budget lives in per-tab session storage — both edges are recorded in [Known limitations](docs/known-limitations.md) (#66). While the tab is offline, the retry and reload buttons are disabled — without a service worker, reloading offline would land on the browser's network-error page instead of back in the app — and they re-enable the moment the browser reports the connection is back.
- An AI quick action that fails because its OpenAI-compatible provider has no API key stored now says so — "AI provider is unavailable — ask an admin to re-enter the API key" — instead of the unrelated "The AI provider returned an error". A provider with no key is a legitimate configuration for a local vLLM or Ollama, so the request is still sent; but since changing a provider's Base URL clears its key (#46), "models attached, key gone" became an easy state to reach, and the resulting upstream 401 deserved a message pointing at the actual cause. The mapping is deliberately narrow: only an upstream 401/403 on a provider with no stored key — a provider whose key was revoked upstream still reports a provider error, not a missing one (#53).
- Test-only: the backlinks endpoint's two safety properties — readers only see source notes they have access to, and the list is capped — now have a combined regression test pinning their order. Each property was tested separately, but nothing failed if the implementation ever capped first and filtered after, which would show readers an empty or incomplete list while burying the titles they may see under a stranger's flood of newer notes. The new case floods past the cap with inaccessible sources and asserts the reader still gets exactly their few visible ones; rewriting the query cap-first was verified to turn it red (#25).
- Test-only: the end-to-end tests' shared note-creation helper now waits for the "Connected" badge before handing the note over for typing, instead of borrowing that precondition from #48's read-only-until-synced behaviour. The flake this guards against — text typed before the collaboration handshake completed was silently lost on reload — was closed as a side effect of #48; the explicit wait keeps the suite stable if editing before first sync ever comes back (#33).
- The integration test harness now drops each throwaway database it creates instead of leaving it behind. Every test provisions its own `test_<random>` database and only closed its connection pool afterwards, so a single full run accumulated several hundred databases in the one Postgres container — until `CREATE DATABASE` started failing partway through and the run went red in a way that looked like a flake but cleared on a rerun (a fresh container). Each database is now dropped when its test finishes, with `WITH (FORCE)` to evict any straggler connection and a drop failure logged rather than allowed to fail an otherwise-green test (#51).
- The editor no longer looks connected while it is offline, and no longer lets you type into a note that never loaded. Previously the badge read "Connecting" identically at second 1 and minute 30, and the editor accepted typing the whole time — worst of all when a note failed to load at all, where you could type into a blank document and lose it on reload. Now a note that has never synced is read-only until it loads, and once a connection has dropped for more than a few seconds the badge escalates to a warning: "Editing offline — changes not synced yet" when there is synced content to merge back, or "Not loaded — offline" when there is not. Brief reconnects (a few hundred milliseconds) do not flash anything (#48).
- A rejected collaboration handshake no longer tells people they lost access to a note when they did not. The server had one rejection reason for three different situations, and the client turned all of them into "You no longer have access to this note", closed the note and returned to the list. So an account that was disabled, or whose sessions were invalidated by a password change elsewhere, produced that notice instead of a sign-out; an unexpected server-side error produced it too. The server now separates a genuine access decision from "this token cannot be used right now", and the client only acts on the former — anything else retries the handshake on the same widening delay used for token failures, which for a revoked session converges on a sign-out within seconds. A revoked share still converges on the same notice it always did. Relatedly, a note that finished deleting while a tab was in its reconnect backoff now says the note was deleted rather than blaming the person's access, for a two-minute window after the delete; past that the server deliberately cannot tell the two apart, because distinguishing them for everyone would turn the connection into a way to ask whether any given note id exists (#35).
- A collaboration token response that arrives after switching notes is now ignored instead of being applied to the note now on screen. The request for the previous note stayed in flight across the switch, and its role landed in the current note's state — worst case, the previous note's `none` arrived while the current one was in its post-revocation retry window and ejected someone from a note they had every right to be in (#36).
- A note that cannot fetch its collaboration token now keeps trying instead of sitting on "Connecting" forever. When the token request kept failing past its retry budget, the connection was left open but unauthenticated with nothing scheduled to try again — so a server hiccup during a page load meant that tab stayed dead until it was reloaded, even after the server recovered. It now restarts the whole handshake on a widening delay, and resets that delay once a connection succeeds (#39).
- A reconnect that was slow to close no longer wedges the connection. The one-second safety net that covers "the socket was already gone" used to give up waiting for the real close event; if that event then arrived, it was read as an ordinary disconnect and nothing reconnected, leaving the editor on "Connecting" until reload (#34).
- Losing access to a note before its collaboration connection is established no longer parks the editor on "Connecting" forever — whether the note was still opening or the connection happened to be reconnecting at the time. When the share is revoked before that handshake completes, the server rejects the handshake itself rather than sending the close message the client was waiting for, and that rejection carried no state change at all. The client now reads it, retries once with a fresh token, and then shows the same "You no longer have access to this note" notice and returns to the note list as any other revocation (#6).
- A single SSO sign-in no longer spends two units of the same rate-limit quota. `GET /api/auth/oidc/login` and `GET /api/auth/oidc/callback` shared one 30-per-minute-per-IP bucket, and a complete sign-in always goes through both — so the usable number of sign-ins was half the advertised one, which offices behind a shared outbound IP hit first. Each endpoint now counts against its own bucket (#16).
- The failed-login throttle no longer grows without bound. Its account and IP records were only dropped when the same key happened to be touched again after 15 idle minutes, so a spray of distinct accounts or addresses left entries behind for the life of the process. Both tracks now share the same bounded map the other limiters already used, and the record evicted first is always the one whose last failure is oldest — the one closest to expiring anyway (#15).
- Deleting an AI provider now also drops it from the degraded set. Nothing else clears that entry — re-entering an API key is the only other path — so the id lingered for the life of the process (#17).
- The password-length hint is generated from the shared `MIN_PASSWORD_LENGTH` constant instead of being written out in each translation, so raising the minimum can no longer leave the UI advertising the old one (#22).

### Changed

- The first page load no longer downloads the note editor. The editor and its collaboration machinery — two thirds of the previous 1.6 MB bundle — only matter once a note is actually opened, but they shipped in the initial bundle that the sign-in page, the note list and the settings dialog all had to wait for. The note page is now loaded on demand: the initial bundle drops to roughly a third of its former size (about 495 KB to 167 KB compressed), opening the first note fetches the editor chunk with the same loading indicator the page already shows while fetching the note, and a CI check now pins both the entry-bundle ceiling and the presence of the split-out chunk so neither regresses silently (#19).
- Email lookups — sign-in, adding a share by email, OIDC account linking — now use an index. Every one of them compares `lower(email)`, but the schema only indexed the raw column, so each lookup walked the whole users table; unnoticeable on a small instance, a real cost as accounts accumulate. The new index is deliberately non-unique: case-variant duplicate emails are allowed to exist, and OIDC sign-in depends on being able to detect that situation rather than having the database reject it — a test pins both the index and that property (#18).
- The re-verification deadline that closes a collaboration connection when its holder loses access is now documented as what it actually is: deliberately shorter than the client's worst-case token-retry backoff (5s vs 7.5s), so a revocation never waits out a retrying client. A false positive costs the affected client a reconnect — and if the backend is still failing, its usual restart backoff and an offline badge until things recover — but never mislabels them as having lost access. The comment next to the constant used to claim the margin covered that backoff, which was false and would mislead anyone tuning either number. Both constants now live in the shared package, and a test pins the deadline-shorter-than-retries relationship so changing either side forces a conscious revisit (#40).
- A refused collaboration connection now leaves a line in the server log — which note, which account, which of six causes, and whether it was refused while connecting, closed after a permission re-check, or closed because the client did not answer that re-check in time — and an unexpected error inside the handshake is logged with its stack trace instead of being flattened into a generic rejection. Since a refusal now navigates the person away rather than leaving them stuck on "Connecting", the report that reaches the maintainer is "I got kicked out", with nothing on either side to say why. The refusal lines are capped per account, with errors on their own budget and a warning when the cap bites, and refusals decided before the token identifies anyone are logged at `debug` so an anonymous socket cannot drive them at all. (The line written when a client misses a re-check is not capped — it is bounded by how many connections that re-check covered.) See [Troubleshooting](docs/self-hosting.md#troubleshooting) (#37).
- A few stray simplified-Chinese characters and one garbled sentence in source comments (#34).
- **Breaking for reverse-proxy deployments:** `X-Forwarded-For` is no longer believed by default. It used to be trusted from any source, which let anyone forge their apparent address and walk around the per-IP login lockout and the OIDC endpoint limits. The new `TRUST_PROXY` setting turns it back on — a list of trusted proxy addresses (IPs, CIDRs, or `loopback`/`linklocal`/`uniquelocal`), a hop count, or `true` for the old behavior. **If you run behind a reverse proxy and do not set it, every visitor arrives as the proxy address and shares one rate-limit bucket**, so five bad passwords from anyone lock out everybody. The server logs a warning at startup when `PUBLIC_URL` is https while the setting is off, and once at runtime when it sees a forwarding header it was told not to trust. Note that your proxy has to send `X-Forwarded-For` for the setting to do anything (nginx does not by default), and a proxy that rewrites `Host` and relies on `X-Forwarded-Host` will now fail image uploads with 403 until `TRUST_PROXY` is set (#13).
- The collab-token rate limit stays keyed on the user, not the note, and the reasoning is now recorded next to it: the limit exists to bound what one signed-in user can cost the database, keying it per note would multiply an attacker's allowance by their note count, and keying it on the address would penalise offices behind one outbound IP (#24).
- The AI session's context value is memoised, so a streaming response no longer rebuilds every consumer — including the portal-mounted toolbar — on each delta (#20).
- `POST /api/auth/login` and `GET /api/auth/me` are typed against the shared `UserDto`, and `GET /api/auth/config` against `AuthConfigDto`. A change to those shapes now fails the build in `apps/server`, where the mistake is, rather than in the web app that consumes them (#21).
- A stray simplified-Chinese character in a source comment (#23).

## [0.1.1] - 2026-08-20

### Added

- Release automation: pushing a `vX.Y.Z` tag publishes the matching GitHub Release, with the notes taken from this file's section for that version. The workflow fails rather than publishing an empty release when a version has no section here, and can be re-run by hand for a tag pushed earlier.

### Fixed

- Markdown pasted from a Windows clipboard renders as blocks again. Line endings were the whole story: the Markdown parser does not normalise CRLF, so `- ` lists and ``` fences stayed literal while headings came through fine — which is why the failure looked arbitrary. The paste handler now normalises before parsing (#28).
- Copying a Markdown file out of VS Code and pasting it produces blocks rather than one code block. VS Code tags the clipboard with the file's language, which previously wrapped the entire paste in `language-markdown`; that tag is now honoured for code and ignored for Markdown files (#27).
- A code snippet copied from a documentation page pastes as a code block again, instead of having a leading `# comment` promoted to a heading (#27).
- A failed session lookup no longer leaves the whole app spinning. When `GET /api/auth/me` fails with anything other than 401, the route guards show an error with a retry button instead of treating the unresolved session as "still loading" (#7).
- Sidebar highlighting and delete-navigation recognise a custom slug regardless of case or Unicode normalisation form, matching how slugs are normalised on save (#8).
- Editing a note title while a save is in flight no longer loses those keystrokes — neither the server's echo nor the error-path reset overwrites what was typed after submitting (#10).
- "Copy link" works on plain-http deployments. `navigator.clipboard` only exists in a secure context, so the button was inert in the LAN mode this project documents; it now falls back to a copy inside the share dialog, and shows the URL in a read-only field when neither route can copy (#9).
- Dark mode no longer flashes a white screen on first paint (#11).

## [0.1.0] - 2026-08-14

### Added

**Server foundation & auth**
- Password-based authentication: environment-variable admin bootstrap (`ADMIN_EMAIL`/`ADMIN_PASSWORD`) that atomically creates the first admin account at startup and forces a password change on first login, plus session cookies (JWT-backed), login/logout, self-service password change, and login rate limiting with exponential backoff/lockout.
- OIDC/SSO login: `GET /api/auth/oidc/login` and `GET /api/auth/oidc/callback` implement the authorization-code + PKCE flow against any OpenID Connect Discovery-compatible identity provider, auto-provisioning new accounts and linking to existing password accounts on a verified email, gated by a per-IP rate limiter; `GET /api/auth/config` lets the client discover whether it's enabled.
- Notes CRUD API with owner/editor/viewer sharing and role-based permissions, and admin user management (create, disable, enable, promote).
- Docker Compose deployment (`app` + Postgres `db`) with a production build, a persistent `uploads` volume, and a trusted-LAN plain-http deployment mode with a loud startup warning.

**Collaborative editing & sharing revocation**
- Real-time collaborative editing (Yjs/Hocuspocus) mounted at `/collab`, with a short-lived collab-token endpoint and role-based auth/re-verification on connect and on token refresh.
- Immediate revocation semantics: admin-disable and share-removal force-close the affected user's live collab connections; note deletion gates out reconnects during teardown.
- Y.Doc persistence with an optimistic lock and bucketed, auto-pruned snapshot backups (`note_state_backups`), plus a documented manual restore runbook (see `docs/backup-restore.md`).
- Browser UI: note list sidebar, app shell, block editor (BlockNote) with collaborative cursors and title editing, canonical note URLs, custom slugs, share dialog with role management, and an admin users page (later migrated into the Settings modal — see below).

**Wikilinks & backlinks**
- `[[wikilink]]` inline content: `[[` trigger, suggestion menu, create-and-link, and three-state rendering (resolved/unresolved/loading) in the block editor.
- Wikilink index sync (`POST /api/notes/:id/links`) with a transactional `links_clock` gate and batched target authorization, submitted by a debounced client-side link-sync watcher.
- `GET /api/notes/:id/backlinks` with inline reader authorization, and a collapsible backlinks section on the note page.

**Image uploads**
- `POST /api/notes/:id/uploads` and `GET /api/uploads/:id`, with multipart size/type limits, magic-byte content-type sniffing, and a per-user rate limit.
- Uploaded blobs are deleted after note deletion commits (best-effort).
- Restored image block with a custom FilePanel: an Upload tab for images, Embed-by-URL only for audio/video/file blocks.

**AI quick actions**
- Bring-your-own-endpoint AI: shared contracts for error codes, SSE events, and action/admin DTOs across `anthropic` and `openai_compatible` provider types.
- `POST /api/ai` SSE proxy (`text/event-stream`) with upstream reasoning/thinking-output filtering, an abort chain, and a per-user rate limit.
- Guarded apply chain in the editor: block-anchor snapshots, hash-gated apply, semantic revert, and wikilink rebinding after an AI edit.
- AI panel with a session state machine, a floating selection toolbar, streaming responses, and a split-pane note layout (editor + AI panel + backlinks, independently scrolling).

**Admin AI configuration**
- Provider/model/action CRUD (`/api/admin/ai/*`) with a connection-test endpoint, shared model resolution, and `GET /api/ai/actions` (only actions that currently resolve to a usable model).
- AI provider API keys encrypted at rest (AES-256-GCM, key derived from `APP_SECRET`); four built-in actions (rewrite/translate/summarize/continue) seeded idempotently at boot, renameable/disableable but not deletable.

**Settings modal**
- Notion-style Settings modal (Account, Users, AI) opened over the background route from the user menu, replacing the standalone `/admin/users` page; shares its password-change form with the standalone `/change-password` page used for forced resets.

**End-to-end testing**
- Playwright end-to-end test suite (`e2e/`) exercising bootstrap, notes, live collaboration, sharing/revocation, AI quick actions, and OIDC login against a stub identity provider, runnable locally via `scripts/test-e2e.sh` and wired into CI as a dedicated `e2e` job on pushes to `main` (and manual dispatch).

### Changed
- Email matching (login, sharing, admin user creation, OIDC account linking) is now case-insensitive: every write path normalizes the address to lowercase, and every lookup compares via `lower(email)`. `alice@example.com` and `Alice@example.com` now resolve to the same account.

### Fixed
- Hocuspocus setup hash-busy handling and collab hook contract corrections found in final review.
- Router `maxParamLength` raised to 512 so astral (surrogate-pair) characters in note references don't 404.
- Toast id generation no longer depends on `crypto.randomUUID`, which is unavailable in non-secure contexts such as LAN plain-http.
- Viewport-locked app shell so the editor, AI panel, and backlinks regions scroll independently instead of the whole page.
- `/admin/users` now redirects (`<Navigate replace>`) to `/settings/users` instead of 404ing, so old bookmarks/links keep working.
- AI action reorder buttons are disabled while a move is in flight, preventing rapid double-clicks from writing duplicate `sortOrder` values that made ordering unrecoverable from the UI.

### Security
- CSRF protection on uploads scoped to `Origin` header validation, with a documented exemption for requests that carry no `Origin` at all (matching legitimate non-browser clients).
- Byte-capped request body draining and an embed-URL scheme whitelist to bound abuse from unauthenticated or rejected requests.
- Outbound AI provider requests (connection test and streaming) use `redirect: "manual"` so a 3xx from a misconfigured/malicious upstream can't cause the custom `Authorization` header to be forwarded to a third-party host — undici only strips `Authorization`/`Cookie` automatically on redirect, not custom-named auth headers.
- AI provider API keys are never serialized into any API response (admin endpoints return a derived `hasKey` boolean instead of the ciphertext).
