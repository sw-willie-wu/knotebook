# On a phone

The phone layout, below 640 pixels. Part of [Known limitations](../known-limitations.md).

- **After a note was opened from outside Knotebook, `‹` replaces the note in the browser history with the list.** Back to notes steps back through the history to the list when the list is still there, also after a reload. A note opened from a link in another app, a bookmark or by typing its address has no list before it, so `‹` swaps that history entry for the list instead of adding one; the system Back button then goes to whatever came before the note, which can be outside Knotebook, rather than returning to the note.
- **Tapping the strip above Settings, Site admin or a group's panel closes it without asking.** On a phone these panels are a sheet with a strip of the page showing above it, and tapping that strip closes the panel straight away, the same as Esc, even when you have typed into a form on it and not saved it (a new password, a new name). What you typed is lost. On a wider window clicking outside the panel doesn't close it.
- **Turning a phone across 640 pixels closes the full-screen search and the sidebar drawer.** Rotating to a window 640 pixels wide or more closes the full-screen search, and rotating back to under 640 pixels closes an open drawer; the note you are on stays.
- **Narrowing a browser window on a computer used with a mouse to below 640 pixels doesn't keep your place in the list or a note.** Below 640 pixels the page itself scrolls, from 640 up the list and the note scroll inside their own panels, so the narrowed window starts them at the top. Turning a phone either way, resizing on a touch tablet (split view included) or unfolding a foldable keeps the same row or paragraph, and widening a window past 640 pixels keeps the paragraph of a note (and the row of the list where the sidebar is shown, from 1280 pixels): the page keeps track of your place while it is under 640 pixels wide, and from 640 up on devices whose screen is narrower than 640 pixels on its short side or whose main pointer is a finger.
- **How the phone layout behaves with an on-screen keyboard, a notch or a home indicator, and the slide-in when a note opens hasn't been checked on a real phone.** The search bar of the list (the one with Cancel, shown while the full-screen search is open) is lifted by the amount the browser reports for the keyboard (browsers that don't report it leave the bar at the bottom of the window, behind the keyboard), a note's floating buttons step aside while the keyboard is up, the page extends under the notches and keeps its controls clear of them, and a note slides in from the right unless the system asks for reduced motion; these were built from the browser's reports and tried only in a desktop browser at phone width. The same goes for scrolling below 640 px, where the list, the search and a note scroll the page itself: whether Safari's toolbars slide away and the page shows under its see-through bottom toolbar, where the header that stays at the top of the page sits while the on-screen keyboard is up, and whether pulling down at the top of the list, the search or a note being edited is kept from reloading the page. For that last one the page asks the browser not to chain the pull to the page (`overscroll-behavior-y: contain`), which Chrome on Android honours; whether iPhone Safari does hasn't been checked.
- **With a selection that crosses two side-by-side columns, the block type button changes only the first column's blocks.** The editor reports the second column as one column block, which is not one of the block types in the list, so it is skipped; the text isn't lost, and undo puts it back in one step.
- **While the dialog for adding or editing a link is open, a collaborator typing before the link shifts where it lands.** The place the link goes is saved when the dialog opens and isn't adjusted for edits made while it is open, so the new address can start a few characters early and leave the end of the old link with its old address; undo puts it back in one step. Links made from the `/` menu behave the same way.
- **A comment about a passage can't be started on a phone.** Below 640 pixels the toolbar over a text selection is hidden, because under a finger it covers the selection and the system's own menu, and the **Comment** button for a passage is in that toolbar. Comments about the whole note work, from **Comments** in the note's ⋮ menu, and the quote of a passage comment written elsewhere still takes you to the passage.
